## 5. זרימות מידע מרכזיות

### 5.1 פרסום — הצינור המחייב (הוקשח 05/08/2026)

```
worktree מבודד מ-origin/main → PR → quality (CI) ירוק → squash merge →
Vercel בונה מ-main → verify-production מוכיח שהקומיט חי → מחיקת הענף
```

הכללים שנגזרים מזה:

- **`main` מוגן**: ‏`quality` הוא status check מחייב, היסטוריה ליניארית (squash בלבד), בלי force-push ובלי מחיקת ענף. ‏`enforce_admins=false` — ליניב נשארת דלת חירום.
- **לעולם לא לעבוד בעץ המשותף** (`Desktop\jerusalem`) — סשנים מקבילים מזיזים בו את ה-HEAD בין פקודה לפקודה. ‏`git worktree add -b <ענף> <path> origin/main` מהצעד הראשון.
- **אימות פריסה הוא הוכחה, לא הנחה**: `Base.astro` מזריק `<meta name="build-commit">` מ-`VERCEL_GIT_COMMIT_SHA`, ו-`scripts/verify-deploy.mjs` ממתין עד שהפרודקשן מגיש בדיוק את הקומיט שנמזג, ואז בודק 200 בכל המסלולים הקנוניים וסמנים מחייבים (מנוע החוברת, תוכן העניינים של השכבה, כותרת הלוח, רצועת ה-WhatsApp). רץ אוטומטית ב-CI אחרי מיזוג, וידנית: `npm run verify:deploy`.
- **לוקפייל**: ה-CI מריץ `npm i -g npm@11` לפני `npm ci` כדי להתאים לגרסה שמייצרת את הלוקפייל בסביבת העבודה; אחרת `npm ci` נכשל ב-EUSAGE.
- ‏`gh` כאן איטי ולעיתים נתקע ב-TLS timeout — לאמת מיזוג דרך `gh pr view --json state`, ופריסה דרך `verify:deploy`, לא דרך fetch בודד.

### 5.3 הספר המדפדף

`src/data/choveret.ts` מגדיר שכבות, פרקים ופריטים. `Booklet.astro` בונה ממנו שער, מפתח לכל שכבה בכפולה אחת — שני עמודים בדיוק, `toc-{slug}` ו-`toc-{slug}-2` (05/08/2026), עמודי משאב, קישורי עומק, שיתוף והורדה. מסלולי `reader/[grade]/[item]` מאפשרים פתיחה ישירה של פריט.

**מכונת המצבים (04/08/2026):** שער ותוכן עניינים חיים בתוך זרימת האתר הרגילה — בלי השתלטות ובלי כפתור "חזרה לאתר"; מצב `is-full` (השתלטות על החלון + נעילת גלילה + כפתור "חזרה לאתר") נגזר אך ורק מהעמוד הנוכחי — עמוד משאב (`it-*`) משתלט, וכל עמוד אחר משחרר. "חזרה לאתר"/Escape חוזרים לעמוד תוכן העניינים האחרון (`lastToc`, וב-deep link — `data-toc` של הפריט) ולמיקום הגלילה השמור. במסך רחב עמוד משאב הוא spread של שני דפי ספר נפרדים (ימין הטמעה, שמאל מידע ופעולות) עם שדרה באמצע. **נגישות ההשתלטות (05/08/2026, ‏#21):** כל מה שאינו החוברת מסומן `inert` + `aria-hidden` בזמן `is-full` ומשוחרר ביציאה, והמיקוד מוחזר לחוברת/לשער (5.15). זהו המימוש הקנוני — **אין להוסיף מעליו `role="dialog"`/`aria-modal` נפרד** (נשקל ונדחה ב-#16 כדי לא לייצר כפילות מול המימוש החזק יותר). **איכות הטמעות (05/08/2026):** כל הטמעה בחוברת עוטפת מסגרת זכוכית אחידה (`item-frame`, זהה ל-`mam-frame`/`mrange-shell` — 8.26) עם שלד טעינה + חשיפת-fade ב-`load` (‏`.frame-skel`; ‏`MafmarRange` מקבל `.mrange-skel` מקביל) — תמיד `pointer-events:none`, עם רשת-ביטחון של 8ש׳, ומכבד reduced-motion. `MafmarRange` מקבל prop `fill` בתוך החוברת (ממלא את הדף בלי כרטיס מקונן; ברירת מחדל false — 8 השימושים העצמאיים לא נגעו).

**מפריד בין החוברת להמחשות (05/08/2026):** שורת `nav.book-links` נמחקה מ-`Booklet.astro` (הוראת יניב). במקומה, ב-`chativat-beynayim/index.astro`, יושב `hr.section-rule` בין `<Booklet>` ל-`<HamchashotEmbed>` — קו `--navy` ברוחב מלא (‏`100vw` עם `margin-inline: calc(50% - 50vw)`), דוהה לשוליים, חוט זהב מתחתיו ומרווח `clamp(3rem, 7vw, 5.5rem)` משני צדדיו.

**מנוע הדפדוף (04/08/2026):** שכבת התצוגה היא StPageFlip (חבילת `page-flip`, ‏MIT) — גרירת פינה אמיתית, קיפול, חזית/גב דף וצל דינמי. ספר עברי מושג בהיפוך סדר העמודים (בלי mirror): "קדימה" שלנו = `flipPrev` של המנוע. מבנה העמודים: שער קשיח ← שני עמודי מפתח לכל שכבה (זוגי מעצם הגדרתו — דף היישור הריק בוטל) ← זוגות משאב (הטמעה+מידע כשני sections) ← כריכה אחורית קשיחה; הסך זוגי כדי שכל spread יתיישר. נקודות רגישות: `destroy()` של המנוע מסיר את ה-host מה-DOM (להחזירו לפני בנייה מחדש); המנוע דורס את attribute ה-style של הדף (משתני צבע חיים על `.page-face`); ה-host חייב להיות צמוד למידות הספר, אחרת flip תוכניתי הופך no-op; קפיצות רחוקות — `turnToPage` (מיידי), סמוכות — `flipNext/Prev` (מונפש). בנייה מחדש (debounced) בכל שינוי מידות/כניסה ויציאה מ-is-full.

## 7. Google Drive — מדיניות שימוש

Drive משמש עבור:

- תמונות מקור ונכסים באיכות מלאה.
- סרטונים, טייקים וקובצי הפקה כבדים.
- מסמכים פרטיים וחומרי עבודה.
- חומרי משרד החינוך, Canva וקובצי מקור לפני אישור לפרסום.

Drive **אינו** מקור האמת של הקוד. קיימים בו עותקי סביבת עבודה הכוללים גם `.git`, `node_modules`, `.vercel`, `dist`, `.astro` ו־`test-results`; אין לסנכרן אותם חזרה לריפו.

לפני שימוש בנכס Drive:

1. אמת בעלות והרשאת פרסום.
2. אמת שהקישור נגיש לקהל היעד ללא התחברות, כאשר הוא אמור להיות ציבורי.
3. העתק לריפו רק נכס שאושר ונדרש לפרודקשן.
4. בצע אופטימיזציה ושמור מידות ויחס מתאימים.
5. אין לרשום במסמך ציבורי מזהי תיקיות פרטיות, מפתחות או פרטי גישה.

- שינוי במספר העמודים עלול לשבור את מפת MAF ואת קישורי העומק.

### חוויית משתמש

- iframe חיצוני יכול להיחסם על ידי CSP/X-Frame-Options; חייב להיות fallback אמיתי.

### אבטחה ופרטיות

- ה־proxy חייב להישאר allowlist קשיח.
- הריפו ציבורי; אין להכניס מידע פרטי, credentials או קבצי Drive שאינם מיועדים לציבור.
- **כלי ניהול אישיים אינם חיים בריפו הזה** (הוראת יניב, 05/08/2026): סטודיו החוברת
  הועבר לריפו הפרטי `yanivmizrachiy/jerusalem-booklet-studio`. הריפו הזה ציבורי,
  ולכן קוד של כלי ניהול — זרימת התחברות, בדיקות הרשאה ולוגיקת כתיבה לריפו — נחשף
  לכל. הסטודיו ממשיך לפרסם לאתר כרגיל (כותב ל-`src/components/Booklet.astro` דרך
  GitHub API עם משתני סביבה ב-Vercel); רק מיקום הקוד השתנה. בתיקייה

## 9. פרוטוקול שינוי חכם

1. סנכרן וקרא את `main` הנוכחי.
2. קרא את סעיפי `RULES.md` הרלוונטיים.
3. זהה מקור אמת יחיד וקבצים מושפעים.
4. בדוק האם קיים נכס או מקור מאושר ב־Drive.
5. נסח תוכנית קצרה, סיכונים וקריטריוני קבלה.
6. צור ענף ממוקד.
7. בצע שינוי קטן ככל האפשר.
8. הרץ בדיקות ממוקדות ואז את שער האיכות הנדרש.
9. בדוק diff, קישורים, RTL, נייד ונגישות.
10. פתח PR עם תוצאות מדויקות.
11. מזג רק אחרי CI ירוק ואימות Vercel.
12. עדכן את `RULES.md`, `README.md` או מסמך זה רק כאשר תחום האחריות שלהם השתנה.

## 10. מתי לעדכן כל מסמך

| אירוע | מסמך |
